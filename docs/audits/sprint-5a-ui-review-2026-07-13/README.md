# Sprint 5A deployed UI review

Audit scope: Dashboard directory, editor, Component and placement-detail disclosures, embedded viewer, full-screen Table, and narrow-screen reflow. Forms and Components directories were captured as comparison surfaces for application-level consistency.

User goal: compose and inspect a Dashboard without losing canvas space, then consume complete paged Tables and visual Components in a viewer that feels native to Tessara. Accessibility target: clear semantic structure, keyboard-operable disclosures, trapped dialog focus, reliable focus restoration, and responsive reflow without hidden actions.

## Overall verdict

The follow-up implementation materially harmonizes Dashboards with the rest of Tessara. Directory hierarchy, search, table treatment, buttons, typography, colors, spacing, and responsive navigation now follow the established Forms and Components patterns. The editor keeps the canvas primary and moves secondary work into shared side sheets. Charts and Tables share a subdued rounded surface without hard component borders, Stat Cards keep their configured fill, and the route-free standard Component Table renderer owns optional title/full-screen presentation without resetting query state. A final clarified annotation follow-up preserves that shared blue-to-teal gradient while reducing its visual contribution to 50% for charts and Tables; Stat Cards remain unchanged.

The review found and drove fixes for full-screen focus restoration, conditionally unmounted sheet focus restoration, two-stage focus restoration from selected preview back to its sheet and opener, dialog disclosure relationships, mobile Dashboard-directory wrapping, desktop action-column overflow, pagination density, and decorative grid-guide noise in the accessibility tree.

## Reuse and organization outcome

- Shared `SideSheet`, `ModalDialog`, and `FullscreenDialog` now own Portal placement, Escape handling, focus trapping/restoration, background inertness, and scroll locking.
- Dashboard editor Components, Placement details, and selected preview use those shared surfaces.
- Forms attached nodes plus Workflow available-node and assigned-user panels also use the shared sheet.
- Shared `TableSearch`, `TablePaginationBar`, `TablePaginationFooter`, and `Button` replace feature-local presentation markup across the touched surfaces; the editor kind picker follows the established Components select pattern instead of reproducing a wrapping feature-local toggle.
- Dashboard detail visibility composes the shared metric-card, `SideSheet`, and `TableSearch` vocabulary rather than retaining a one-off key/value table and unbounded node-name string.
- Viewer presentation now follows Component semantics instead of one universal placement wrapper: charts compose intrinsic titles on the shared soft surface, Stat Cards render their configured intrinsic surface directly, and Tables delegate optional title/full-screen behavior to the route-free standard Component Table renderer.
- The root-local orphaned searchable-table implementation was removed.

## Remaining non-blocking consolidation choices

- Decide whether the next tranche should migrate the remaining legacy Forms, Workflow, Dataset, and Component hand-rolled sheets/modals immediately or treat that as a focused post-Sprint refactor.
- Decide whether controlled column selectors and header filter popovers should become shared presentation primitives while their client-backed and server-backed state engines remain separate.
- Split the large Dashboard editor and Component viewer files by canvas/inspector/preview and table/request/render responsibilities when that refactor can receive dedicated regression coverage.

## Evidence limits

This review exercised visible desktop/tablet/phone states, semantic browser snapshots, keyboard close behavior, focus restoration, paging-state continuity, and browser console output. It does not claim full WCAG conformance: a screen-reader pass, automated contrast measurement, zoom beyond the sampled responsive widths, and platform-specific high-contrast modes remain separate verification work.
